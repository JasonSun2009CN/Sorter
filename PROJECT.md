# Personal File Manager

> A local-first file organization tool that learns what your files are, tags them automatically, and lets you decide how they should be organized.

## 1. Project Vision

Personal File Manager is a privacy-first desktop application for intelligently organizing files on a local computer.

The application scans a user-selected file or folder scope, extracts metadata and content features, uses local machine-learning models to predict useful tags, and presents the results to the user.

The user then defines how files should be organized.

The application **never directly reorganizes files without user confirmation**.

Core principle:

```text
Machine understands the files.
User defines the organization.
Application previews the changes.
User approves the operation.
Application safely applies the changes.
```

## 3. MVP Goals

The MVP should answer one question:

> Can a user give the application a messy folder and safely reorganize it with significantly less manual work?

### MVP must support

* Selecting a file or folder as the scan scope
* Recursive file scanning
* Basic file metadata extraction
* Support for common document/image formats
* Local text extraction where possible
* Automatic tag prediction
* Confidence scores for predicted tags
* Manual tag editing
* User-defined organization rules
* Organization preview
* Conflict detection
* Explicit confirmation before modifying files
* File movement
* Basic operation history
* Undo / rollback for the last operation

### MVP should NOT include

* CLI
* Cloud backend
* User accounts
* Synchronization
* LLM API calls
* Remote file processing
* Complex automation
* Full-featured file manager replacement
* Advanced AI agents

## 4. Privacy Principles

The application is local-first.

```text
User Files
    |
    v
+----------------------+
| Local Processing     |
|                      |
| Scanner              |
| Feature Extraction   |
| ML Classification    |
| Organization Engine  |
+----------------------+
```

No file content should leave the user's machine by default.

The MVP should not require:

* an account
* an API key
* an internet connection
* a cloud backend

Potential future versions may optionally support external models or services, but local processing remains a core design principle.

## 5. Tagging System

Tags are divided into three categories.

### System Tags

Automatically generated from deterministic metadata.

Examples:

```text
pdf
image
large-file
recently-modified
duplicate
archive
```

### Learned Tags

Generated by machine-learning models.

Examples:

```text
mathematics
physics
chemistry
school
programming
finance
travel
```

### User Tags

Created or modified by the user.

Examples:

```text
important
semester-1
MIT
review
archive
```

Conceptually:

```text
File
 |
 +-- System Tags
 |
 +-- Learned Tags
 |
 +-- User Tags
```

A future version may learn from user corrections.

Example:

```text

    -> Mathematics 82%

User:
    -> Mathematics
```

Store the correction as training data.

Future predictions can then become:

```text
User Corrections
        |
        v
Personal Training Data
        |
        v
Personalized Classifier
        |
        v
Better Predictions
```

The goal is for the application to gradually adapt to each user's organization habits.

## 8. Organization Engine

Machine learning should NOT determine the final directory structure.

Instead:

```text
ML
 |
 +--> "What is this file?"
 |
 v
Tags

User
 |
 +--> "How should files with these properties be organized?"
 |
 v
Organization Rules
```

Example:

```text
Rule:

Subject -> File Type

School/
    Mathematics/
        PDF/
        DOCX/
    Physics/
        PDF/
        DOCX/
```

Another example:

```text
Year -> Extension

2026/
    PDF/
    DOCX/
    Images/
```

Another:

```text
Custom Tag -> Directory

Important/
School/
Archive/
```

Rules may eventually support combinations of multiple attributes.

## 9. Preview Is a Core Feature

Preview is not an optional convenience.

It is a safety mechanism.

Before applying changes, the application must show exactly what will happen.

Example:

```text
ORGANIZATION PREVIEW

87 files will be moved.

----------------------------------------------
Current Path                  New Path
----------------------------------------------
Downloads/math1.pdf           School/Math/math1.pdf
Downloads/physics.pdf         School/Physics/physics.pdf
Downloads/report.docx         Documents/report.docx
----------------------------------------------

Warnings:
- 2 filename conflicts
- 1 duplicate file
- 4 files have low-confidence tags

[ Cancel ]                  [ Apply Changes ]
```

The user should never have to trust a black-box operation.

---

## 10. Safety Requirements

The application must follow a conservative philosophy.

### Never silently:

* delete files
* overwrite files
* rename conflicting files
* move files without confirmation

### Before applying changes:

```text
Scan
  |
Classify
  |
Plan
  |
Preview
  |
Confirm
  |
Apply
```

### Rollback

Each organization operation should create a reversible operation record.

Example:

```text
Operation #42

old:
Downloads/math.pdf

new:
School/Mathematics/math.pdf
```

Undo should restore the original state whenever possible.

## 17. Long-Term Vision

The long-term goal is not merely to build an automatic folder sorter.

The larger vision is:

```text
                  Personal File Manager

                         |
                         v
                  Understand Files
                         |
             +-----------+-----------+
             |                       |
             v                       v
        Semantic Tags          File Metadata
             |                       |
             +-----------+-----------+
                         |
                         v
                   Smart Search
                         |
                         v
                 Smart Organization
                         |
                         v
                Personal File System
```

The ultimate product should make the physical organization of files less important.

Instead of remembering:

```text
School/Grade11/PureMath/Chapter5/...
```

the user should be able to think:

```text
"Find my calculus notes from this semester."
```

and let the application determine where those files actually are.

---

## 18. Definition of Success

The MVP is successful if a user can:

```text
1. Select a messy folder.
2. Scan it.
3. Receive useful automatic tags.
4. Correct those tags.
5. Choose an organization strategy.
6. Preview every change.
7. Apply the changes safely.
8. Undo the operation.
```

The product should save enough time and reduce enough organizational friction that the user would voluntarily use it again on another folder.
